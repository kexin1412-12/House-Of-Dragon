# PRD: 立场追踪 v1

> 版本：v1 草稿
> 日期：2026-05-01
> 范围：HotD S1 限定，不泛化

---

## 1. 背景与目标

### 1.1 现状

我们做的是 HotD 互动观影 companion。已有的功能（角色内心对话、关系图、叙事 X 光）都解决"看不懂"——给观众更多信息、更深的角色理解。但**它们都没有解决一件事：观看本质是被动的**。HotD 这种政治叙事密度极高的剧，观众坐在沙发上消化两小时信息，真正的情绪输出发生在观看之后——上 reddit、上豆瓣、上微博，在那里讨论"你站谁"。

也就是说：**用户已经在站队，只是站在我们产品之外。**

### 1.2 战略洞察

HotD 的核心冲突结构不是"善 vs 恶"，是"绿党 vs 黑党"。这是一个被剧本明确设计成必须站队的二元结构——而且是一个**会在剧情推进中不断被新信息挑战的**站队。S1E5 你站雷妮拉时她还是被亏待的合法继承人；S1E8 你发现她孩子根本不是莱诺的；S1E9 维赛瑞斯死前那句"埃里兹"被绿党听成"亚莉森"……每一次新信息揭示，立场都被重新审视一次。

**这是别的剧很少有的产品机会**：它的剧本天然支持"过去的选择被打脸"机制。这是 Spotify Wrapped、BuzzFeed 性格测试都没有的东西，因为它们的输入是静态的，而立场追踪的输入是会被剧情打回去的。

### 1.3 战略目标

1. **把社交平台上"你站谁"的讨论承接到产品内**——让产品成为立场表达和验证的载体，而不只是观看辅助
2. **建立一个会随剧情推进被打脸/被验证的活轨迹**——让用户对自己的观影记忆产生 ownership
3. **季末产出可分享物**——拿到 social loop，承接现有讨论流量

### 1.4 成功指标

| 类型 | 指标 | 目标 |
|---|---|---|
| 北极星 | 完成 ≥3 次阵营选择的用户占活跃用户比例 | TBD（v1 跑数据） |
| 留存 | 在 S1E1 完成选择 → 在 S1E5 仍参与选择的转化率 | ≥ 50% |
| 病毒 | 看完 S1E10 的用户中，分享轨迹卡的比例 | ≥ 15% |
| 反指标 | 开启互动模式后主动关闭的比例 | ≤ 20% |

反指标必须放在前面看——这个功能最大的失败模式不是没人玩，而是因为打断观影把核心观看体验做坏了。

## 2. 用户与场景

### 2.1 目标用户

**P0 — HotD 重度观众**
- 已经看过至少一遍，会回头补设定、看二创、上社交平台讨论
- 已经有立场倾向，本功能给他们一个表达 + 验证 + 被挑战的载体
- 这部分人是病毒传播的种子

**P1 — HotD 新观众**
- 第一次看，立场未形成
- 本功能引导他们形成立场，并在后续打脸中产生记忆点
- 转化关键期是 S1E1-E3，错过就只是路人观众

### 2.2 核心场景

**场景 A：转折点站队**

S1E5 红堡晚宴，亚莉森穿绿裙登场那一刻，产品弹出选择卡：

> 如果你是红堡中的一位领主，你会站起来向王后行礼，还是坐着不动？
>
> - 起身行礼 — "她的孩子确实有危险"
> - 纹丝不动 — "誓言就是誓言"
> - 端起酒杯假装没看见 — "现在选边太早了"

用户做选择，附内心理由。选择被记录。

**场景 B：被打脸的回顾**

用户在 S1E5 选了站雷妮拉。三集之后看 S1E8，剧情明确揭示她三个儿子都长着斯壮家的棕发。本集片尾产品弹出回顾卡：

> 你在 S1E5 选择了支持雷妮拉，理由是"誓言就是誓言"。
> 但现在她的三个儿子都长着斯壮家的棕发。
> 你还站她吗？

用户面对自己过去的判断。可以坚守、动摇或叛变——三种选择都有合法的内心理由。

**场景 C：季末分享**

看完 S1E10 后，产品生成一张精致的立场轨迹图：曲线 + 阵营标签 + 性格化点评。用户可以分享到社交平台。朋友看到，触发新用户冷启动。

### 2.3 用户旅程关键节点

```
首次触发(S1E1末) → opt-in决定 → 第一次站队 → ...
   → 第一次回顾打脸(机制是否成立) → ...
   → 季末轨迹图(累积价值是否成立)
```

每一个节点都是流失点。Phase 1 必须先打通"opt-in 是否合理"，再去验证"打脸机制是否上瘾"。

## 3. 产品方案

### 3.1 功能清单（MoSCoW）

| 优先级 | 功能 | 说明 |
|---|---|---|
| **Must (P0)** | 阵营选择卡 | 关键转折点弹出，3 选项 + 内心理由 |
| **Must (P0)** | 回顾卡 | 剧情反转后挑战旧选择，本功能的灵魂 |
| **Must (P0)** | Opt-in 流程 | 首次触发时询问，默认关闭互动模式 |
| **Must (P0)** | 季末轨迹图 | 个人轨迹 + 性格化标签，可分享 |
| **Must (P0)** | 触发点配置后台 | 编辑用，最小可用 |
| Should (P1) | 选择历史回看 | 用户主动查看自己所有选择 |
| Should (P1) | "暂时静音本集"按钮 | 降低互动疲劳 |
| Could (P2) | 跨季继承 | S2 上线后用 S1 立场作起点 |
| Could (P2) | 立场类型百分比 | 需要数据量级 |
| Could (P2) | 朋友轨迹对比 | 社交增强 |

### 3.2 关键交互逻辑

**触发频率**
- 阵营卡：**每集 1-2 个**，编辑人工预定（不算法触发）
- 回顾卡：剧情反转的"信息揭示完成"那一刻后，本集片尾或下次打开 app 时

**选项设计原则**
- 始终 3 选项：站绿党、站黑党、观望/中立
- **每个选项必须附一句"内心理由"**——让选择不是按按钮，是做一个有说服力的选择
- 观望永远是合法选项，不强迫站队（强迫站队会逼出大量随机选择，污染轨迹）

**轨迹度量**
- 每个阵营选择记一个分数：站黑党 +1 / 站绿党 -1 / 观望 0
- 累积形成 sparkline
- 季末按总和给阵营标签 + 按轨迹形状给类型标签

### 3.3 边界与限制（Not in Scope）

明确砍掉：

- ❌ **道德困境投票**（戴蒙杀妻、骑士求私奔等场景）——它们不映射到阵营，进不了轨迹图。后续可以做成独立功能，v1 不做。
- ❌ **与 character-inner 联动**——v1 立场追踪是只读的旁观功能，不影响其他系统。耦合留到 v2。
- ❌ **关系图盾牌图标 / 百科推送针对性**——同上，避免跨系统耦合。
- ❌ **百分比社会比较**（"72%的用户站黑党"）——v1 用户量级不够，数字会假。
- ❌ **泛化到非 HotD 剧集**——v1 只做 HotD S1。S2 看 v1 数据决定。

## 4. 策略设计

### 4.1 触发点编辑策略

**核心决策：不算法触发，人工标注。**

每集由内容编辑选 1-2 个真正具有阵营张力的场景。鉴别标准：

> "这个选择是否真的存在两边都合理的阵营立场？如果'对的答案'太明显，不触发。"

举例：
- ✅ S1E5 绿裙登场（明确的政治站队信号）
- ✅ S1E8 私生子棕发（对老选择的打脸）
- ❌ 戴蒙杀妻（不映射阵营）
- ❌ 维赛瑞斯加冕（没有立场分歧空间）

标注内容（每条触发点）：

```yaml
episode: S1E5
scene_id: green_dress_entrance
timestamp: "31:00"
trigger_type: faction_choice
options:
  - id: black_loyalty
    label: 起身行礼
    sublabel: 站亚莉森
    inner_voice: "她的孩子确实有危险..."
    score: -1  # 站绿党
  - id: white_oath
    label: 纹丝不动
    sublabel: 站雷妮拉
    inner_voice: "誓言就是誓言..."
    score: +1  # 站黑党
  - id: neutral
    label: 端起酒杯假装没看见
    sublabel: 观望
    inner_voice: "现在选边太早了..."
    score: 0
recall_targets:
  - episode: S1E8
    trigger_after_scene: bastard_hair_reveal
```

### 4.2 回顾卡触发逻辑

**输入信号**
- 用户某次阵营选择 + 后续剧情中编辑预先标注的"立场打脸点"

**匹配规则（编辑预定义）**
- "S1E5 站雷妮拉的选择 → 在 S1E8 棕发揭示后挑战"
- "S1E5 站亚莉森的选择 → 在 S1E10 战争爆发时验证"

**触发时机**
- 揭示场景结束后，本集片尾结束时弹出（首选——情绪余温还在）
- 兜底：如果用户没看完本集，下次打开 app 时弹（在剧情外环境）

**剧透边界**
- **严格基于用户观影进度触发**，绝不基于剧集发布日。如果用户跳着看没看到揭示场景，回顾卡推迟到他看到为止。

### 4.3 轨迹生成策略

**简单规则，不上模型**：

- 每个阵营选择 ±1 / 0
- 累积形成 sparkline
- 总和判断最终阵营标签：
  - `> +3` → 黑党
  - `< -3` → 绿党
  - 之间 → 中立摇摆

**类型标签（编辑预设 5-7 种）**：

| 轨迹形状 | 类型标签 | 性格化点评（节选） |
|---|---|---|
| 一路黑党 | 坚定黑党 | "你认死理，认到底，认到不在乎对错。" |
| 黑党→动摇→黑党 | 理想主义摇摆者 | "你相信誓言，但被现实暴击过，又选择回来。" |
| 一路绿党 | 务实绿党 | "你不关心血统，你关心谁的孩子能活到明天。" |
| 中段叛变绿党 | 觉醒派 | "你看清了制度的虚伪，从此再不回头。" |
| 全程观望 | 旁观者 | "你不是没立场，你是不愿被任何阵营定义。" |

**关键：类型描述靠预设文案兜底，不靠协同过滤。**v1 没有数据做聚类。

### 4.4 数据冷启动

- v1 不依赖用户量级数据
- 不放百分比统计——等到 ≥5k 同集观看用户后再加
- 类型标签和点评是预设文案，跟用户量无关，从第一个用户起就能用

### 4.5 A/B 测试方案

Phase 1 后开始：

- **实验 1：opt-in 措辞** — "想加入互动观影吗" vs "想看看你是黑党还是绿党吗" vs "想被剧情打脸吗"。验证哪种钩子转化最高。
- **实验 2：回顾卡触发时机** — 本集片尾 vs 下次打开 app 时。验证情绪余温和打断容忍度的权衡。
- **实验 3：每集触发数** — 1 个 vs 2 个。验证密度和疲劳的临界点。

## 5. 技术依赖

### 5.1 数据需求

**已有**
- 用户身份
- 用户观影进度（episode + timestamp）

**新增**
- `stance_choices` 表：`user_id, episode_id, scene_id, choice_id, score, created_at`
- `stance_triggers` 配置表（编辑后台读写）
- `stance_recalls` 配置表（编辑预定义的打脸链）

### 5.2 接口

- 客户端定时上报观影进度 → 服务端检查是否到触发点 → 弹卡
- 选择保存接口（异步即可）
- 季末轨迹生成接口（用户主动调用）

### 5.3 性能要求

- 触发判断 P95 < 200ms — 不能让弹卡卡顿
- 选择保存可异步 — 不阻塞用户
- 触发点配置 hot reload — 编辑改完立即生效，不用发版

## 6. 风险与降级

### 6.1 主要风险

**风险 1：互动疲劳（最大风险）**
- 用户因为打断观影体验关闭功能，甚至 uninstall
- 缓解：opt-in 默认关；每集封顶 2 个；提供"暂时静音本集"按钮；反指标实时监控
- 红线：如果反指标 > 20%，立刻降低触发频率

**风险 2：编辑成本**
- 每集 1-2 触发点 + 每个触发点 3 选项文案 + recall 链 = 不便宜
- 缓解：v1 只做 HotD S1（10 集 × 1.5 平均 = 约 15 个触发点），可控；建立标注模板和审稿流程
- 长期：必须接受这是个内容驱动的功能，不是纯算法功能

**风险 3：用户 game it（拿到漂亮轨迹）**
- 用户为拿到"理想主义摇摆者"反向选择
- 缓解：v1 不暴露类型映射规则；类型文案做得够诚实（"你认死理"、"你又骗自己又骗别人"）以至于刷分没意义
- 接受：少量用户会刷，不影响整体

**风险 4：剧透边界**
- 回顾卡如果在用户没看到揭示场景前弹出会剧透
- 缓解：触发严格基于用户进度，不基于发布日；测试用例必须覆盖跳集观看场景

**风险 5：轨迹图分享后落地页是空的**
- 朋友点开分享卡进来，没有自己的轨迹可看
- 缓解：分享卡落地页要有"开始你的轨迹"CTA，引到 S1E1 的 opt-in 流程

### 6.2 降级方案

| 故障 | 降级 |
|---|---|
| 触发点服务挂 | 客户端不弹卡，正常看剧，无感降级 |
| 轨迹生成失败 | 提示"轨迹生成中，稍后查看"，不阻塞分享卡之外的功能 |
| 编辑没及时配置某集 | 那集没触发点，用户看完跳过即可，不报错 |
| 用户跳集，观影进度乱 | 触发点按用户实际看到的最新场景判断，不按计时 |

## 7. 里程碑

### Phase 1 — MVP（4 周）

**范围**：仅阵营选择卡，仅 S1E1-E3，无回顾卡，无轨迹图

**交付**：
- 阵营选择卡组件
- 触发点配置后台（最小可用）
- 选择保存
- Opt-in 流程
- 反指标埋点

**验证目标**：
- 用户愿意被打断吗？
- 打断的代价值不值？
- opt-in 转化是多少？

**Go/No-go 决策**：opt-in 转化 < 20% 或反指标 > 30%，停下来重新设计

---

### Phase 2 — 回顾机制（3 周）

**范围**：配置 S1E1-E3 → S1E5-E7 的回顾链，上线回顾卡

**交付**：
- 回顾卡组件
- recall 链配置和触发逻辑
- 推进至 S1E1-E7

**验证目标**：
- 被打脸是否产生记忆点？
- 是否产生讨论欲（社交分享、朋友推荐）？

**这个 Phase 是整个功能的灵魂。如果回顾卡跑不通，季末轨迹图就只是个 quiz 结果，没有 ownership。**

---

### Phase 3 — 季末产物（3 周）

**范围**：轨迹图、类型标签、分享卡，推开 S1 全集

**交付**：
- 轨迹生成
- 类型标签 + 性格化文案
- 分享卡 UI（精致设计）
- 落地页 + 新用户 onboarding

**验证目标**：
- 分享率
- 病毒系数 K
- 季末活跃留存

---

### Phase 4 — 数据沉淀（持续）

- 用户量到 5k+：加入百分比统计
- 跑 A/B 实验（opt-in 措辞、触发时机、密度）
- 评估 S2 是否做继承
- 评估道德困境是否独立成功能（不并入轨迹图）

为避免范围蔓延，明确这些 v1 **不写**：

- 不写 character-inner 如何读 stance state
- 不写关系图如何加盾牌图标
