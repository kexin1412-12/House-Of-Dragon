# 设计：让「共谋者」功能演示页忠实复刻产品

- 日期：2026-05-21
- 选手：陈可欣 · 赛题一 · 共谋者
- 目标文件：`conspirator-demo.html`（单文件演示页）

## 1. 背景与目标

`conspirator-demo.html` 是一个单文件、可离线打开的功能演示 / 路演页，
用来在评委打不开线上 demo（`house-of-dragon-phi.vercel.app`，需 VPN）时，
仍能展示「共谋者」产品。

现状：页内已手搓 4 个交互（立场卡、四色声部、符号热点+防剧透、AI 解析面板），
但都是写死的零散样例数据，分支很短（如四色声部追问只是 `(i+1)%` 循环切题）；
产品里的两个招牌功能——**人物关系图 + 人物档案**、**故事线时间线**——页内完全缺席。

**目标**：在保持「单文件、离线可开」的前提下，让交互和数据尽量贴近真实产品：
补齐两个招牌交互、深化现有 4 个、把数据换成从真实 KB 策展的真数据、再做一遍视觉/动效抠细。

## 2. 选定方案与关键决策

- **方案 A · 单文件忠实复刻**：保持一个可移植 HTML，从真实 KB / 快照抽真数据
  inline 进 `<script>`（冻结快照、不联网）。
  - 否决 B（嵌真组件 / iframe）：profile 深读、流式回答都要后端，破坏离线性。
  - 否决 C（只轻量打磨）：不补关系图 / 时间线就达不到「复刻」。
- **关系图还原度 = 策展核心子集**：~8 个核心角色，复刻「点角色 → 冲突线 + profile 侧栏」
  的关键交互，不做全量 18 节点的拖拽缩放（落地页里太重也别扭）。
- **头像 = 引用 Vercel 图片 URL + 字母圈兜底**：文件最小；联网时显示真人脸，
  离线/无 VPN 时优雅退化成「家族色字母圈」，绝不显示裂图。

## 3. 全局硬约束（来自长期偏好，落地必须遵守）

1. **不暴露内部细节**：可见文案不得出现文件名 / 路径 / JSON 字段名 / 内部 ID /
   反引号代码引用 / "本剧 KB" 这类元层级措辞。真实数据字段（`convergence_hint`、
   `arc_so_far`、`is_canonical`、`short_identity` 等）一律映射成干净中文标签。
   现有英文模块名（StanceCard / CharacterPanel 等）作为既有设计元素**保留**，
   不新增裸字段名。
2. **不打分**：立场 / 投票 / 选择类交互不打分、不归类、不聚合，连底层 score 都不算。
   "我的立场轨迹" 只**列出**用户的选择本身。"观望" 永远是合法选项。
3. **点空白关 profile**：关系图 profile 侧栏开启后，panel 之外任何空白点击都走
   渐进关闭（profile → 冲突高亮 → …），一次剥一层。这段 fallback 必须在。
4. **配色分区**：按语义用项目既有的 灰蓝(理性)/紫(情感)/红(本能)/琥珀(直觉)/
   绿(绿党)/绯红(品牌) 分区，不要每个 section 都堆金/绯红。
5. **时间戳以真实 KB 为准**：所有触发点 / 符号 / 时间线节点的时间戳取自真实 KB
   的 scene end_time / timestamp，不手填、不口算。
6. **中文标签查歧义**：新加的中文 label 先 sanity-check 有没有撞日常词。

## 4. 数据来源（真实 KB → 策展冻结快照）

实现时从下列真实文件抽取、人工策展成精简对象，inline 进 HTML 的 `<script>`：

| 交互 | 真实数据源 |
|---|---|
| 关系图 + profile | `client/public/relationship-graph/_family-tree.json`、`_profiles-house_of_dragon_05.json`、`_scene-focus-…`、`_char-events-…` |
| 故事线时间线 | `server/kb/storyline/house_of_dragon_05.json` |
| 立场卡 | `server/kb/stance/house_of_dragon_05.json`（10 触发点，每个含 prompt_lines / options.inner_voice / speculation.convergence_hint / speculation.by_option） |
| 四色声部 | `server/kb/dialogue_riffs/house-of-the-dragon.json`、`characters/house-of-the-dragon.roleplay.json` |
| 符号热点 | `server/kb/symbols/house-of-the-dragon.json` |
| AI 解析面板 | `server/kb/lore_cards/house-of-the-dragon.json` |

头像：`https://house-of-dragon-phi.vercel.app` + `_family-tree.json` 里的 `portrait_url`，
`onerror` 回落到字母圈。

## 5. 模块设计

页内每个交互是一个**独立 IIFE 模块** + 自带 `const DATA = {...}`，互不共享状态。
单文件内仍保持 6 个清晰、可独立验证的块。

### 5.1 关系图 + 人物档案（新增 · 交互演示 ⑤）
- **角色子集（拟定 8 人，实现时按 `_family-tree.json` 的真实 character_id 核对）**：
  韦赛里斯、戴蒙、雷妮拉、亚莉森特、奥托·海塔尔、莱诺·瓦列利安、科利斯·瓦列利安、雷妮丝。
- **布局**：手排紧凑家族树 SVG —— 婚姻横杠（"夫妻" pill）、子女桥（trunk→bus→legs，"子女" pill）、
  跨代婚姻斜线（戴蒙-雷妮拉）。节点 = 圆头像 + 中英名 + 称号牌 + 龙伴小圈。
- **交互**：点角色 → 该角色的冲突/关系线高亮（敌对/盟友/血亲/秘密/友好，带关系标签），
  无关节点变暗；右侧 profile 侧栏滑入，字段映射成中文标签：身份 / 深度解读 /
  至今的剧情节点 / 血与火 · 背景 / 龙伴。
- **关闭**：点 panel 外空白 → 渐进关闭（profile → 高亮）。
- **头像**：Vercel URL，`onerror` 回落家族色字母圈。
- **边界**：输入 = 策展的 `characters[] / kin_edges[] / conflict_edges[] / profiles{}`；
  输出 = DOM 交互；不依赖其它模块。

### 5.2 故事线时间线（新增 · 交互演示 ⑥）
- 用真实故事线 KB 的节点（摘要 + 关联角色/符号 + 时间戳）。
- 时间轴上未播节点**锁定**（模糊 + "等播到这里再揭晓"），拖一条进度条 / 点击渐进解锁，
  → 展开该节点摘要 + 关联角色/符号。主打"防剧透渐进解锁"。
- **边界**：输入 = 策展的 `nodes[]`（含 t / title / summary / refs）；自带一条 cursor 进度条。

### 5.3 立场卡（深化）
- 换成真实触发点数据，策展 3–4 个（真 scene_label / 时间戳 / prompt_lines /
  options.label + inner_voice）。
- 选**剧情线选项**（`is_canonical`）→ 展开 convergence_hint（"剧情本就如此"）。
- 选**非剧情线选项** → 展开 `speculation.by_option` 对应的反事实推演（流式打字）。
- 底部"我的立场轨迹"：仅按时间**列出**用户做过的选择（场景名 + 所选项），**不打分、不聚合**。
- 支持在 3–4 个触发点间步进（上一/下一）。

### 5.4 四色声部（深化）
- 换真实角色扮演台词；每角色更多问题。
- 追问改成**真分支**：每个回答带其自身的 2–3 个跟问（带立场标签），点击进入对应真实回答，
  不再 `(i+1)%` 循环。
- 四色保留：蓝理性 / 红本能 / 紫情感 / 琥珀直觉；每轮含 外在台词 + 双声部独白 + 潜台词 + 跟问。
- 轮次计数保留；"严格遵守当前集数信息边界，绝不剧透" 文案保留。

### 5.5 符号热点 + 防剧透（深化）
- 换真实符号 KB：更多光点、真时间戳、真分类（色彩编码/伏笔/文化梗…）。
- 保留进度条按 cursor 过滤未来符号 + 跨集回看（callback）。
- 字幕内关键词高亮 popover 保留（如 goose）。

### 5.6 AI 解析面板（深化）
- 换真实 lore / 分层数据；更多开场问题。
- 保留 [事实]/[解读]/[推测] 分层 + lore 卡 + 逐字流式。

### 5.7 视觉 / 动效（横切）
- 给交互块套**类播放器外壳**（faux 进度条与 cursor 概念联动）、profile 滑入过渡、
  流式打字更顺、reveal 动画沿用。
- 按 §3.4 语义分区上色，弱化金色独大。

## 6. 不做（YAGNI）

全量 18 节点拖拽缩放、真后端 / 真流式、真识脸、base64 内联头像、把整个 KB 塞进页面。

## 7. 验证方式

- 浏览器打开 `conspirator-demo.html`，逐个走查 6 个交互：点击/步进/拖动均有预期反馈。
- Console 无报错。
- 断网（或不开 VPN）打开：所有文字与交互正常，头像优雅退化为字母圈（不裂图）。
- 抽查可见文案：无文件名/路径/字段名/内部 ID 泄漏。
- 立场轨迹：确认无任何分数/排名/归类出现。
- 关系图：profile 开启后点空白能逐层关闭。

## 8. 实现顺序（供 plan 参考）

1. 数据策展：从 §4 各源抽取 → 6 个 inline DATA 对象（先关系图 / 立场 / 故事线，体量最大）。
2. 新增模块 5.1 关系图、5.2 时间线。
3. 深化 5.3–5.6。
4. 5.7 视觉/动效统一抠细 + 全局约束复查 + §7 验证。
